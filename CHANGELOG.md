# Changelog

All notable changes to engram are documented here. The format follows
[Keep a Changelog](https://keepachangelog.com/en/1.1.0/); versions follow
[Semantic Versioning](https://semver.org/) while the project is pre-1.0
(minor bumps may change behaviour, as noted below).

## [Unreleased]

### Fixed
- A stdio start no longer bridges its per-process scoping away (#87, P1). `engram mcp` / `dist/interfaces/mcp/server.js` with `ENGRAM_SCOPE` or `ENGRAM_READ_SCOPES` in the environment — every Hermes profile child, or any host following `docs/integrate-your-agent.md` — used to bridge to a healthy daemon, which ran each forwarded call under *its* env: every profile wrote `global` and read every scope, silently. Such a start now runs inline without probing, with the reason on stderr (`running inline (ENGRAM_SCOPE=hermes:career is per-process; the daemon would ignore it)`). The daemon's `/health` gained `dbPath`; with `ENGRAM_DB_PATH` set the bridge is used only when it matches the daemon's, otherwise inline (`ENGRAM_DB_PATH=… but the daemon serves …`). A daemon that does not report `dbPath` (older build) keeps bridging as before.
- `forget` no longer honours `scope: "global"` as a scope override when the server's own env pins reads (`ENGRAM_SCOPE` / `ENGRAM_READ_SCOPES`): an env-pinned stdio child (the Hermes memory-provider transport) could pass it to delete, or search for and delete, another tenant's memories (#109). The override still works from an unrestricted server. The tool description says so; the `tool-schemas` snapshot is re-recorded for that sentence only.


### Changed
- Test scaffolding shared instead of copied (#126, part of the #114 over-engineering burn-down). No behaviour change and no test lost: `tests/mocks/embeddings.ts` replaces eleven copies of the hash-based embeddings `vi.mock` factory, `tests/mocks/llm-fetch.ts` the four `stubFetch` / `makeAnthropicMock` copies in the `*-factory` suites, `tests/mocks/fake-worker.ts` the two `FakeWorker` classes; `tests/helpers.ts` gains the raw row inserts (`insertEntity`, `insertRelationship`, `insertCluster`, `insertBridgeScore`, `insertConversation`, `insertExchange`, `insertMemory`), `createTestMemory`, `makeExchanges` and the built-CLI guard (`builtCli`, `itBuilt`), and loses its `cosineSimilarity` copy (tests import `src/_core/search/vector.ts`) and the one-caller `createTestFixture` / `createSyntheticToolCall`. `vitest.config.ts` sets `test.unstubEnvs`, so suites isolate env with `vi.stubEnv(key, undefined)` instead of hand-rolled save/restore loops.
- MCP server trims (#119, part of the #114 over-engineering burn-down). Every tool's `inputSchema` is now generated from its zod schema (`z.toJSONSchema`, io `input`), replacing about 700 lines of hand-written JSON Schema; `tests/interfaces/mcp/tool-schemas.test.ts` snapshots the full ListTools surface of all 16 tools. Names, descriptions and annotations are unchanged. Visible differences: unbounded integer fields (`show.startLine`/`endLine`, `recall_drill.result_index`, `fetch_snippets` ranges, `ingest_turn.turn_index`) advertise `"integer"` instead of `"number"` (the validator always rejected fractions), `ingest_turn` `tool_calls[]` items no longer claim `additionalProperties: false` (never enforced), and the defaults the handlers already applied are now on the schema (`recall` budget 1500 / dateBasis `filed` / depth `shallow` / sources / reinforce, `recall_session` budget 3000, `commitments` status / limit / budget, `ingest_turn` source). `src/graph/format.ts` renders explore and reflect results once with an `xml` (MCP) / `text` (CLI) switch — output is byte-identical. `recall_session` returns `sessionId` on its result for worker affinity instead of the dispatcher scraping it out of the XML. The worker pool keeps the per-call timeout, the kill-and-respawn at 2× the timeout and respawn-on-exit, and loses the never-set `hangMultiplier` / `readyTimeoutMs` options, the generation counters and its three Error subclasses (same messages, plain `Error`).

### Removed
- Scripts and packaging dead weight (#125, part of the #114 over-engineering burn-down). `scripts/preflight.cjs` drops the per-Node-ABI bookkeeping (`NODE_ABI_MAJORS`, `PREBUILT_NODE_MAJORS`, `nearestPrebuiltMajor`, the `nvm use <major>` hint) and the node-gyp forensics: every native module is N-API, so the verdict is the static target table, confirmed against the shipped binary when the package is on disk (better-sqlite3 still reports `compiled locally` when node-gyp built it). Printed verdicts are unchanged; `--json` no longer carries `target.nodeMajor`. `scripts/sync-manifests.cjs --check` now checks the versions, `package.json` `mcpName` and the registry's 100-character description cap only — manifest shape is `claude plugin validate` / `mcp-publisher validate`'s job in the same CI jobs. Deleted `scripts/check-deps.sh` (no caller), `prompts/reflect.md` and `prompts/summarize.md` (never read), the `integrations/hermes-plugin/README.md` tombstone, the 2.8 MB `assets/galaxy-view.webp` duplicate (the README hero now uses `assets/view-galaxy.webp`), the `sync-manifests` npm script (the `version` hook and `check-manifests` cover both modes) and `.mcp.json` from the npm tarball (it exists for developing inside the checkout).
- Adaptive chunking (#117): `src/semantic/adaptive-chunker.ts`, `ExtractionConfig.chunkingStrategy`, `config.dream.chunkingStrategy` and `ENGRAM_CHUNKING_STRATEGY`. It was unreachable — no caller ever selected it and the env value was never passed to the extractor — so every extraction already used the fixed 25/5 windows and nothing changes. `chunk_metadata.avg_density` stays in the schema and is now always NULL.
- The legacy superpowers conversation-index importer (#115, ponytail burn-down #114): `engram import-legacy`, the deprecated `engram migrate --source` / `--batch-size` / `--force` forwarding, `src/migration/migrate.ts`, `types.ts`, `backfill-entity-conversations.ts` and `add-informativeness-columns.ts` (the columns it added have been part of the schema since 0.2.0). It was a one-shot personal migration that hardcoded a project exclusion and had already run on the only machine that needed it.
- `engram validate --source`: the row-count and content comparison against a legacy database went with the importer, and the "search quality" check — which matched eight hardcoded English words and passed when any one returned a row — is gone because it asserted nothing. `engram validate [--fix]` keeps the embedding, FTS5 and memory-index checks; the code moved from `src/migration/validate.ts` to `src/interfaces/cli/validate.ts`. CLI: 26 commands.

## [0.4.0] - 2026-09-18

First release that ships the Claude Code plugin, the `engram mcp` daemon bridge, `engram mcp install`, `forget`, `engram setup`, `doctor --fix` and `update --rollback` (PRD issues #50 #53 #55 #58 #61 #63 #65) plus the Dependabot majors (#68–#73, #72). The 0.3.0 tarball on npm predates all of it, so the plugin's `npx -y @devinmlowe/engram@<version> mcp` pin only works from this version on. Windows + Node 22 note: see the better-sqlite3 13 entry below (#84).

### Added
- `ENGRAM_LLM_TIMEOUT_MS` — per-request LLM timeout for every tier (default 120 s); the `extraction smoke` budget never undercuts it.
- `engram setup` and `engram doctor --fix` (#61; decision #62). `engram doctor` grew two checks — `env file` (after `data dir`: `~/.config/engram/env` present with mode 600, `[--]` when missing or group/other-readable) and `extraction smoke` (last: one real extraction over the most recently ingested conversation, or the bundled `prompts/smoke-conversation.json` when nothing is indexed, with the last 3 exchanges clipped to 2 000 characters each under a hard 60 s budget, reporting `tier=<ollama|openai|openrouter|anthropic> memories=N` or every tried tier's `CascadeError` reason plus the variables to set; facts from a real conversation are consolidated into the store like any other memory but stamped `source=smoke` — new `MemorySource` value, `ConsolidateOptions.source`, and the extractor result now carries the cascade `provider` — so `engram memories list` finds them and `forget` removes them; the fixture is never written and the smoke never creates a database; `--no-smoke` skips it and `engram update`'s verification runs `doctor --no-smoke`). A check can now carry a `fix` (`src/interfaces/cli/doctor.ts`: the manual equivalent, whether it needs confirmation, and `apply()` which remediates and re-runs the check); `engram doctor --fix [--yes]` applies every non-ok check's fix and prints `[fixed|applied|skipped|failed] <check>: <new verdict>` followed by `manual: <command>`, so users learn what happened, and a second run says `Doctor --fix: nothing to fix`. Remediations: create the service env file (mode 600, dir 700, a commented template of every supported variable; `chmod 600` when wider — never rewriting an existing file), give a model cache inside `node_modules` its durable home (`ENGRAM_MODEL_CACHE_DIR='<data dir>/models'` written to the env file, the downloaded weights moved, the value adopted in-process, other shells told what to export), `ollama pull <model>` when Ollama answers without the configured model (confirm-gated: asked on a terminal, `--yes` otherwise, skipped with the command printed), start an installed-but-stopped MCP daemon through its supervisor and wait for `/health` (not installed → hint only), and `engram mcp install <first host present>` when nothing is registered (Claude Code first; skipped by the installer when the plugin is installed, #60). `engram doctor --strict` exits 1 on any non-`[ok]` line. Everything the checks and fixes touch is behind an injectable `DoctorContext`. `engram setup [--yes] [--sync|--no-sync] [--no-daemons|--daemons=<ids>] [--host <id...>] [--no-smoke] [--json]` (`src/interfaces/cli/setup.ts`, orchestration only — the `init` and `sync` bodies moved to `first-run.ts` so it runs the very same code) walks doctor → init → sync (asked on a terminal) → `mcp install` for every host whose config dir exists (the Hermes plugin deploy is offered when profiles carry it) → **all three services by default** (MCP HTTP daemon, dream timer, visualizer) through the shipped installers via `services.ts` `installService` — a service already installed and running is left alone, the visualizer line names its port and loopback bind (`ENGRAM_BIND` requires `ENGRAM_WEB_TOKEN`), the Linux visualizer (no installer) is reported, and `loginctl enable-linger` stays a separate question that `--yes` never answers — then `doctor --fix` with the same `--yes` semantics, the extraction smoke, and a summary table with next steps. Every step prints a numbered header with its manual equivalent. When the dream timer is installed but no LLM tier answered, setup ends with `[warn] dream timer installed but no LLM tier is reachable — nightly runs will not extract until a provider is configured (OLLAMA_HOST / ENGRAM_LOCAL_MODEL, OPENROUTER_API_KEY, ANTHROPIC_API_KEY, ENGRAM_OPENAI_BASE_URL + ENGRAM_OPENAI_MODEL)` and exit 0; exit 1 only on a required doctor failure or a failed `init`. The README quick start is now `npx … preflight` → `npm i -g` → `engram setup`. The installer scripts skip `npm run build` on a packaged install (`dist/` without `src/`) and, with the launchers and `systemd/` units, are now part of the npm tarball so `engram setup` works from `npm i -g`. CLI: 27 commands. Tests: `tests/interfaces/cli/doctor-fix.test.ts`, `smoke.test.ts`, `setup.test.ts` (every remediation, the smoke with a stubbed provider, the full setup with fakes incl. Windows `.ps1` installers).
- `engram update --rollback` + install-path sanity check + daily version notice (#65; decision #66). Before it changes anything, `engram update` now persists a rollback plan at `<data dir>/updates/<stamp>.json` — prior version and git sha, install kind and root, backup dir, the services that were running with their start commands, plugin deploy targets, target version, the database's schema version, the pre-update row-count snapshot and a `progress` marker advanced at every step (`planned` → `stopped` → `backup` → `snapshot` → `code` → `migrated` → `restarted` → `verified` → `done`, or `failed:<step>`) — so the file exists even when the update aborts at step 1; the newest 10 are kept (`--list-rollbacks`). `engram update --rollback [<stamp>] [--yes]` (`src/interfaces/cli/rollback.ts`) is **code-only by default**: stop the services → `git checkout <sha> && npm ci` or `npm install -g @devinmlowe/engram@<previous>` → `engram migrate schema` with the *restored* build in a child process → restart what was running → the same verification (`--version`, `doctor --json`, `/health`, `stats --json` counts at least the snapshot); `engram.db` keeps everything written since the update because migrations are additive (the caveat is printed). `--restore-data` also copies the backup back (`engram.db` + WAL + `archive/`, archive merged with the backup winning, WAL checkpointed) and is refused when the update ran with `--no-backup`. When a step after the code swap fails, `runUpdate` offers the rollback: `--yes` performs it, a terminal is asked `Roll back to <previous>? [y/N]`, a script gets the exact command — and the backup is restored automatically only when the failed verification showed counts below the snapshot; every rollback prints its mode and that `models/` is not backed up (#54), and records `rolledBack: {at, mode, ok}` in the plan. `/health` not answering at verify time now fails verification. Schema version: `SCHEMA_MIGRATIONS`, `SCHEMA_VERSION`, `schemaVersion(db)` and `BREAKING_MIGRATIONS` (empty today) in `src/_core/db/schema.ts`; a code-only rollback across a breaking checkpoint is refused with the `--restore-data` hint. `engram doctor` gained an `install path` check (`src/interfaces/cli/install-path.ts`): every `engram` on `PATH` (symlinks and shim scripts resolved, `engram.cmd` on Windows) against the install `engram update` upgrades — `[--]` listing every path plus the fix (`npm uninstall -g` with the other tree's npm, or reorder `PATH`) when there are two trees or the first binary is another install, never `[FAIL]`; `engram update --plan` prints the same warning (never a blocker). Daily cached version check (`src/interfaces/cli/update-check.ts`): `engram update --check` caches its answer 24 h in `<data dir>/cache/update-check.json` (one network call per day, bounded by a 6 s timeout, failures cached too); `doctor`, `health`, `stats`, `search`, `sync` and `reflect` print one stderr line `engram X available (you have Y) — engram update` (never with `--json`, never from `engram mcp`), the daemon's `/health` JSON carries `update: {current, available, checkedAt}` from the cache, nothing ever updates itself, and `ENGRAM_NO_UPDATE_CHECK=1` disables the lookup and the notice. `ExecOptions.timeoutMs` (exit 124) on the shell adapter.
- One-command host registration (#50; decisions #51, #52): `engram mcp install claude|codex|cursor|hermes [--all] [--project] [--transport http|stdio] [--dry-run] [--force] [--inline-token] [--json]`, `engram mcp uninstall <host>` and `engram mcp status [--json]` (subcommands of `mcp`; bare `engram mcp` is still the stdio server/bridge). `install` edits the host's own config — `~/.claude.json` (`CLAUDE_CONFIG_DIR` honoured; `--project` → `.mcp.json`), `~/.codex/config.toml` (`[mcp_servers.engram]`; `--project` → `.codex/config.toml`), `~/.cursor/mcp.json` (`--project` → `.cursor/mcp.json`) — or deploys the Hermes plugin through `interfaces/hermes-plugin/deploy.sh` to the same targets `engram update` uses. Transport: HTTP `http://127.0.0.1:<port>/mcp` when the daemon answers `/health` (the doctor/bridge probe), else stdio `node <install>/dist/interfaces/cli/index.js mcp` (which bridges itself once a daemon runs); the reason is printed, `--transport` overrides. Token: never a literal — when `ENGRAM_MCP_TOKEN` is set or lives in `~/.config/engram/env`, Claude gets `"Authorization": "Bearer ${ENGRAM_MCP_TOKEN}"`, Codex `bearer_token_env_var = "ENGRAM_MCP_TOKEN"`, Cursor `Bearer ${env:ENGRAM_MCP_TOKEN}` (formats verified against the Claude Code, Codex and Cursor docs, fixture-tested); `--inline-token` writes the literal with a warning and mode 600. Writes are atomic (temp file + rename, mode kept) with the previous content in `<file>.bak`; other servers, unrelated keys, indent and trailing-newline state survive byte-for-byte and a second run is a no-op. With the Claude Code plugin installed the user-scope entry is skipped (unless `--force`) and `status` lists the plugin as a registered host. `status` reports, per host, registered / points at this install / daemon `/health` / whether `ENGRAM_MCP_TOKEN` resolves in the current environment, with the macOS `launchctl setenv`, Linux `environment.d` and Windows `setx` hint for GUI-launched hosts. `engram doctor` gained a `hosts` check (`[ok]` / `[--]`, never `[FAIL]`). README install is three commands (`npx … preflight`, `npm i -g`, `engram mcp install claude`) with the JSON moved to "Manual configuration"; `docs/integrate-your-agent.md` and the user guide say to run the command instead of hand-editing.
- Plugin-marketplace and MCP-registry distribution (#58; decisions #59, #60). `.claude-plugin/plugin.json` now runs the published npm package — `mcpServers.engram` is an inline `npx -y @devinmlowe/engram@<version> mcp` (it used to point at `../.mcp.json` → `node ./dist/...`, which `claude plugin validate` rejected and which only worked with Claude Code opened inside the checkout). New `.claude-plugin/marketplace.json` makes this repo its own marketplace: `/plugin marketplace add devinmlowe/engram` then `/plugin install engram@engram`. The plugin bundles the five portable slash commands (`commands/recall.md`, `remember`, `explore-graph`, `reflect`, `engram-connect`) with tools named `mcp__plugin_engram_engram__<tool>`; `engram-show-graphs` and `rlm-recall` stay personal. New `server.json` for registry.modelcontextprotocol.io (`io.github.devinmlowe/engram`, npm artifact, stdio, `runtimeHint: npx`) and `package.json` `mcpName` for the registry's ownership check. `scripts/sync-manifests.cjs` copies the `package.json` version into all three manifests (`npm run check-manifests` / the npm `version` hook; CI job `manifests` also runs `claude plugin validate`). New `.github/workflows/release.yml`: a `v*` tag verifies, `npm publish --provenance`, then publishes the registry entry via `mcp-publisher login github-oidc`. README gained "Install as a Claude Code plugin" above the manual JSON, `MCP_TIMEOUT` for the cold first `npx` start and `npm i -g` / the daemon as warm paths.
- Daemon-aware stdio entry (#58, #60): `engram mcp` (and `dist/interfaces/mcp/server.js` without `--http`) probes `GET /health` on the daemon port (`--port`, `ENGRAM_MCP_PORT`, default 9907) and, when the engram daemon answers, runs as a thin stdio ↔ Streamable-HTTP bridge (`src/interfaces/mcp/bridge.ts`) — an MCP client to the daemon's `/mcp` plus an MCP server on stdio forwarding `tools/list`, `tools/call`, `ping` — that opens no database and loads no embedding model; otherwise it runs inline as before. `engram mcp --standalone` / `ENGRAM_MCP_STANDALONE=1` force inline. One stderr line names the mode and reason. The bridge forwards `Authorization: Bearer $ENGRAM_MCP_TOKEN`, presents the host's `clientInfo` to the daemon (so `forget`'s actor stays the host), reconnects once after a daemon restart and sends `tools/list_changed`, forwards daemon errors verbatim and exits on stdin EOF. `engram mcp` also gained `--http` / `--port`.
- `forget` MCP tool + memory inspection surface (#55; decisions #56, #57). `forget` takes `memory_id` (every recalled `<semantic>` now carries an `id` attribute) or `query` + `confirm`: query mode returns `<forget_candidates>` with ids and deletes only when `confirm` is true and exactly one memory matches (a single result, or a single result whose content equals the query), so an agent can never delete on a weak match. A forget is one transaction: soft delete (`memories.deleted_at` / `deleted_by`, `is_active = 0`), the sqlite-vec and FTS5 rows removed immediately (out of every recall path — vector, FTS, hybrid search, session drill, reinforcement, decay), a `memory_changes` row with `before` = content and the MCP client's `clientInfo.name` (or `cli`) as actor — carried through the HTTP worker pool as a `ToolCallContext` — a `memory_suppressions` content hash so the dream extract phase does not re-extract the statement from the same exchanges, and graph detachment: `mention_count` decremented on the entities the memory evidenced, `stale_since` stamped on rows that reach zero evidence, never a graph deletion. The dream prune phase hard-deletes forgotten memories older than `ENGRAM_FORGET_RETENTION_DAYS` (default 30; `0` = next run) and removes `stale_since` rows with no remaining evidence regardless of age; `hard: true` / `--hard` bypass retention. Annotated `readOnlyHint: false`, `destructiveHint: true`; honours `read_scopes` unless `scope: "global"`. 16 tools total. New CLI `engram memories list|show|edit|delete|restore|purge|log` (`show` prints the source conversation title and archive path, source exchanges, extractor source, `extraction_basis`, scope, FSRS stats, graph evidence with `stale_since`, and the change log); `engram validate` no longer needs `--source` and fails on vector/FTS rows for forgotten or missing memories, with `--fix` to repair; `reflect` reports `stale_nodes` and the flagged entities; the Hermes plugin exposes `engram_memory_forget` (http) / `engram_forget` (stdio) alongside remember. Schema checkpoint `forget_v1`.
- Native-dependency preflight (#63): `scripts/preflight.cjs` (still the npm `postinstall` hook) now reports, per native module (`better-sqlite3`, `sqlite-vec`, `onnxruntime-node`), whether a prebuilt exists for the running Node ABI + platform + arch + libc — `[ok] prebuilt`, `[warn] compiled locally` (node-gyp artefacts found next to the binary) / `will compile (needs python3 + C++ toolchain)`, `[FAIL] unsupported`, `[--] unknown (<reason>)` — followed by the exact fix for the OS and `nvm use <major>` when the gap is a Node major. It inspects `node_modules` after an install (prebuild-install tarball vs local build, the `sqlite-vec-<os>-<arch>` platform package, `bin/napi-v*/<platform>/<arch>` for onnxruntime-node) and falls back to its static `NATIVE_DEPS` table before one; probes never throw. New `engram preflight [--strict] [--json] [--expect <spec>]` runs it without opening the database or loading models, so the README install snippet starts with `npx @devinmlowe/engram preflight` (decision #64). `engram doctor`'s `better-sqlite3` / `sqlite-vec` lines end with the same `prebuilt — …` / `compiled locally — …` verdict and its `platform/arch` line names the libc and Node ABI. The README "Supported platform/arch set" table is generated from that table (`scripts/supported-platforms.cjs`, checked by a test); musl (Alpine) is documented as unsupported — better-sqlite3 has musl prebuilds but sqlite-vec and onnxruntime-node ship glibc-only Linux binaries (verified on `node:22-alpine`). CI now runs Node 22 and 24 on ubuntu, `ubuntu-24.04-arm`, macos and windows with `preflight --strict --expect prebuilt`, and asserts the documented `unsupported` verdict on `windows-11-arm` (experimental) and in a `node:22-alpine` container; Dependabot groups native-module bumps separately and a workflow labels them `native-dep`.
- Generic OpenAI-compatible LLM provider (#45): a new `openai` tier for OpenAI, LiteLLM and self-hosted gateways, configured by `ENGRAM_OPENAI_BASE_URL` (a bare origin gets `/v1`), `ENGRAM_OPENAI_MODEL` (activates the tier), `ENGRAM_OPENAI_API_KEY_ENV` (the *name* of the env var holding the credential, read at call time and never stored or printed) and optional `ENGRAM_OPENAI_TEMPERATURE` (omitted by default; many gateways reject it). `ENGRAM_LLM_PROVIDERS` sets the tier order independently of what is configured (default `ollama,openai,openrouter,anthropic`; a tier left out is never tried). OpenRouter now runs on the same client (`src/_core/llm/providers/openai-compatible.ts`), so both routes share retry, sanitisation and tool-call parsing. `engram doctor` gained an `llm providers` check naming the order, each tier's endpoint/model and its key variable.
- Multi-tenant scoping across every layer (#25): `scope` column (default `global`, indexed, checkpoint `graph_scope_v1`) on `exchanges`, `entities`, `relationships` and `commitments`. `ingest_turn` stamps exchanges; dream extraction stamps new entities, relationships and commitments with the conversation's scope, and a graph row seen again from a different scope widens to `global` (shared knowledge, never duplicated per tenant). Episodic recall, graph search, `explore`, `explore_selective` and `commitments` honour `read_scopes` (the three tools gained per-call `scope` / `read_scopes` params); `reflect` stays global. Helpers in `src/_core/db/scope.ts`.
- Optional bearer-token authentication (#27): `ENGRAM_MCP_TOKEN` makes the HTTP MCP daemon's `/mcp` require `Authorization: Bearer <token>` (`/health` stays open for supervisors) and is required before `ENGRAM_MCP_HOST` may be non-loopback; the visualizer honours `ENGRAM_WEB_TOKEN` (falling back to `ENGRAM_MCP_TOKEN`) on every route but `/api/health`, accepting a bearer header, `?token=` once (which sets an HttpOnly cookie for the page's API calls and SSE), and refuses a non-loopback `ENGRAM_BIND` without a token. The Hermes plugin sends `token` from `engram.json`. Tokens are compared in constant time and never logged.
- `engram update`: controlled self-update modelled on `hermes update` — `--check` (current vs available for git checkouts and npm installs), `--plan`/`--dry-run` (read-only: install kind, every directory holding an `engram.db`, model cache, every service with its supervisor and restart command, Hermes plugin deploy targets, backup path, blockers), and the run: backup `engram.db` + WAL + `archive/` → stop services through their supervisor (launchd / systemd user units / Task Scheduler, `src/interfaces/cli/services.ts`) → snapshot counts → durable model cache → `git pull --ff-only` + `npm ci` or `npm install -g` → data-dir move + schema migrations with the new build → restart MCP then visualizer, redeploy the Hermes plugin → verify doctor, `/health`, and that no count dropped, printing rollback steps otherwise (#44).
- `engram migrate` now means install/data migration: `data-dir` (detects a pre-0.2.0 `~/.local/share/engram` next to an empty new default and moves the data; refuses when two dirs both hold a database), `model-cache` (durable `ENGRAM_MODEL_CACHE_DIR`, copies downloaded models out of `node_modules`), `schema` (opens the db once and lists `schema_migrations`); every topic supports `--dry-run`. The legacy conversation-index importer is `engram import-legacy --source <path>`; `engram migrate --source` forwards with a deprecation notice for one release (#44).
- `engram stats --json` prints the row counts `engram update` compares before/after.
- README: one-command update per platform, and a Windows "safe update and data-directory migration" section (preflight, install vs restart, stale process on the port, verification incl. the MCP handshake). `install-mcp-daemon.ps1 status` reports `dataDir`, `dbPath`, `legacyDbPath` (#13).
- macOS/Linux supervision for the MCP HTTP daemon: `scripts/install-mcp-daemon.sh` (`install|uninstall|start|stop|restart|status`, every verb waits on `/health`) renders `launchd/com.engram.mcp.plist` or `systemd/engram-mcp.service`, both running the new `scripts/run-mcp-daemon.sh` launcher, which sources `~/.config/engram/env`. The resolved data directory is rendered into the service so daemon and CLI share one database; `status` warns about a second legacy database. `install` retires a hand-written `ai.hermes.engram-mcp` agent on the same port. The server honours `ENGRAM_MCP_PORT` when `--port` is absent, and `engram doctor` gains an `mcp daemon` check that probes `/health` (#28).

### Changed
- `better-sqlite3` 12.11.1 → 13.0.3 and `sqlite-vec` 0.1.7-alpha.2 → 0.1.9 (Dependabot #72). better-sqlite3 13 is N-API: its binaries are Node-version independent and ship inside the npm tarball as `prebuilds/<platform>[musl]-<arch>.node` for eight targets, so `scripts/preflight.cjs` no longer tracks Node ABIs for it (`abis: null`) and the README table lost its per-Node-major columns. **Dropped: 32-bit ARM Linux (`linux-arm` / `linuxmusl-arm`, armv7)** — 13.x publishes no prebuild for it, so `npm install` on armv7 now compiles better-sqlite3 from source (the preflight reports `will compile` with the toolchain fix instead of `prebuilt`; sqlite-vec never supported armv7, so the Engram verdict there stays *not supported*). Node 23/25 no longer need a source build. Caveat: npm 10 (Node 22) still runs the implicit `node-gyp rebuild` at install because the lockfile does not carry the package's `gypfile: false` — `binding.gyp` compiles nothing when a bundled prebuild matches, but `node-gyp configure` needs Python 3 and the Node headers from nodejs.org (cached under `~/.cache/node-gyp`) — on Windows that means a Node 22 install now needs a node-gyp-recognised Visual Studio + Python 3 or it fails at `npm install` (CI `windows-latest, node 22`; workaround `npm install -g npm@11`, which skips the script like Node 24 does). The `^12.11.1` pin (#63) that this replaces existed to keep Node 26 prebuilds; it is moot now.
- Durable model cache by default (#53): `modelCacheDir` now resolves `ENGRAM_MODEL_CACHE_DIR` → `$HF_HOME/hub` → `<data dir>/models` instead of falling back to `node_modules/@xenova/transformers/.cache`, which every `npm install` / `npm ci` / global upgrade wiped. The first model load in a process (and `engram init` / `engram migrate model-cache`) moves a legacy `node_modules` cache into the resolved dir — one rename, or copy + size verification across filesystems, tolerant of two processes racing — and logs one line, so upgrading never re-downloads. `engram doctor`'s `model cache` line reports `durable: yes|no` (`no` only for an explicit path inside `node_modules`) and which tier chose the dir; `engram migrate model-cache` is a no-op with a message once the default applies; `engram update --plan` and the failure rollback steps state that `models/` is not backed up (re-downloadable; rollback re-downloads if the cache is missing — decision #54). `EngramConfig.modelCacheDir` is now always a string.
- Writer coordination (#26): recall reinforcement retries `SQLITE_BUSY` three times with jittered backoff and then skips the round instead of logging an error (the recall itself never fails); `recordCheckpoint` opens its read-then-write as `BEGIN IMMEDIATE`; the consolidate phase yields between conversations; `runDream` takes an advisory `<data dir>/tmp/dream.lock` so a concurrent `engram dream` fails fast (`DreamLockedError`) instead of contending for hours. The concurrency model is documented in `src/_core/db/SPEC.md` and exercised by `tests/core/writer-contention.test.ts`.
- The CLI `--version`, MCP `serverInfo` and `engram update` all read the version from `package.json` (`src/_core/version/index.ts`) instead of three hardcoded literals.
- The Windows installers/runners and the bash installers default the data directory the way the CLI does (`%LOCALAPPDATA%\engram` / `$XDG_DATA_HOME/engram`, legacy `~/.local/share/engram` fallback) instead of always the legacy path (#13, #44).
- Hermes plugin log messages point at `scripts/install-mcp-daemon.sh status` instead of the hand-written `ai.hermes.engram-mcp` LaunchAgent.

### Fixed
- `engram extract`, `engram setup` and the extraction smoke accept a configured OpenAI-compatible tier (`ENGRAM_OPENAI_MODEL` + key) on its own; `initExtractor` only knew Anthropic, OpenRouter and Ollama since #45.
- `engram mcp` started nothing: the CLI subcommand only `import()`ed `server.js`, whose entry runs solely when that file is the process entry point (since the worker-pool change), so the command exited 0 without a transport. `server.ts` now exports `startMcpServer` / `connectStdioInline` and the CLI calls them (#58).
- `engram update` pulls with an explicit `origin <branch>` (a branch without upstream tracking made the bare pull fail), and any failure restarts the services it stopped before printing the rollback steps, so an aborted run never leaves the MCP daemon or visualizer down (#46).
- `remember_batch` items are closed (`additionalProperties: false`, zod `.strict()`) like `remember`; an unknown key on an item is rejected instead of ignored (#43).
- `memories_fts` ranks the `context` column at 0.25 of `content` (`bm25(memories_fts, 1.0, 0.25)`), so the constant Hermes mirror context note can no longer outrank a real content match (#42).
- `reflect` is routed through `interfaces/shared/reflect.ts` on both the CLI and MCP surfaces; the interface-parity test asserts it (#38).
- `scripts/install-daemon.sh` no longer requires `launchctl` on Linux, so its systemd branch is reachable (#28).
- Hermes plugin circuit breaker is truly half-open: after the cooldown exactly one probe call is allowed, and a failing probe re-opens the breaker with the failure count intact, so parked turns are no longer posted one by one and dropped while the daemon is still down. A queued turn that fails on transport is now kept and retried; only a turn the live server rejects (`isError` / JSON-RPC error, new `EngramMcpRejected`) is dropped (#41).

## [0.2.0] - 2026-09-17

### Upgrade notes

- **First dream run after upgrading re-extracts every conversation once.** The extract fingerprint now hashes exchange content instead of message lengths (#23), so every previously fingerprinted conversation looks changed. A full pass over a large archive takes hours; bound it with `ENGRAM_DREAM_MAX_CONVERSATIONS=<n>` for the first run(s). Duplicate memories are not created (the consolidator dedups), and later runs skip unchanged conversations as before.
- **Hermes plugin must be redeployed and Hermes restarted** — `interfaces/hermes-plugin/deploy.sh` (add `ENGRAM_PLUGIN_PROFILES="a b"` for profile copies), then restart the gateways; running sessions keep the old module until then (#17, #20).
- Restart the MCP HTTP daemon, dream daemon and visualizer after `npm run build` so they load the new `dist/` (see README "Updating an existing installation").
- Schema migrations are additive and run on the first database open; no manual step.

### Added

- MCP `ingest_turn`: record one user/assistant turn of an external agent session; idempotent upsert on `session_id` + `turn_index`; the conversation's `scope` is inherited by every memory the dream pipeline extracts from it (W2).
- Per-request tenant scoping: `scope` / `read_scopes` on `recall` and `recall_session`, `scope` on `remember` / `remember_batch`, overriding `ENGRAM_SCOPE` / `ENGRAM_READ_SCOPES` for that call (W1).
- CLI `engram export` / `engram import`: JSONL v1 transfer of memories, entities, relationships and commitments; import is idempotent by id (newer wins), regenerates embeddings, FTS and vectors (W11).
- Recall reinforces the memories it returns (FSRS access bookkeeping and stability growth); `reinforce: false` on the recall tools and `engram search --no-reinforce` opt out (W8, #22).
- `ENGRAM_LOCAL_MODEL_FALLBACKS`: comma-separated Ollama models tried in order when `ENGRAM_LOCAL_MODEL` is not pulled; `engram doctor` gains an `ollama` line showing the resolved local model and whether the tier is active (#16).
- `CascadeError` from the LLM factory: when every tier fails, the error names each tier and its reason (config skip vs runtime failure); config skips are warned once per process, runtime failures every call (#15).
- `DreamReport.collapsedCandidates` and a `Collapsed dupes` line in the `engram dream` summary; `DreamReport.skippedUnchanged` / `Skipped unchanged` for fingerprint-skipped conversations (W12, #23).
- Dream noise reduction: intra-batch and run-level near-duplicate collapse before insertion, a transient-status memory tier (importance ≤ 0.3, stability 7 days) and model-supplied `confidence` in extraction (W9).
- `engram dream --force`: re-extract conversations even when their fingerprint is unchanged (W12).
- Hermes plugin (http transport): per-turn ingestion via `ingest_turn` (`sync_turns`, default true), built-in MEMORY.md/USER.md mirror (`mirror_memory_writes`, default true), `prefetch_contexts` (default `["primary"]`), primary-only write gating, a warm-up recall on `initialize()`, and visible timeout misses (rate-limited warning + ⚠️ recall indicator) (W3–W5, #17).
- Contract tests: no direct Anthropic clients outside `_core/llm/providers`, SPEC/README path references resolve, MCP tool annotations pinned, CLI/MCP capability parity (W10, #22, #29).

### Changed

- Hermes plugin `timeout_secs` default 2.0 → 4.0 (cold recall on a ~17K-memory store measured ≈ 2 s); `is_available()` is config/deps only and the `/health` probe moved to `initialize()` → `unavailable_reason()` (W5, #17).
- All LLM calls (semantic and graph extractors, consolidator, commitments pass) go through the `_core/llm` factory cascade Ollama → OpenRouter → Anthropic; the consolidator therefore surfaces "no tool_use in either Anthropic model" as a transient per-batch error instead of a silent noop (W6, W7, #30).
- Extract fingerprint hashes each exchange's text (length-prefixed) with its id, index and timestamp, so same-length in-place edits are re-extracted (#23).
- `recall`, `recall_session`, `recall_drill` keep `readOnlyHint: true`; their descriptions state the access bookkeeping and the `reinforce: false` opt-out (#22).
- Ollama tier config skips report "Ollama not reachable" vs "model X not found; available: […]" distinctly (#16).
- `package.json`: version 0.2.0; `prepublishOnly` builds and runs the test suite (#31).

### Fixed

- Cascade failures no longer report only the Anthropic tier's "API key required" — the real failing tier (e.g. OpenRouter 401, Ollama timeout) is in the error and in dream extract checkpoints' `error_message` (#15).
- Extract phase recorded two error checkpoint rows per conversation per run (initial + retry); `recordFailure` now updates the existing row and increments `attempt_count` (#24).
- Consolidate phase records a failure checkpoint per batch and continues with the next batch; a tool_use-less response is classified transient (#30).
- Dream checkpoint `error_class` is `provider` rather than `unknown` for rejected API keys, so they are not pointlessly retried (#15).
- Consolidator refuses supersession ping-pong (a candidate restating a memory that the existing one already superseded) (W12).
- Stdio Hermes provider: fallback loader registers the Hermes contract module in `sys.modules` before exec (W0).
- CLI `engram explore <unknown>` prints `Entity not found: …` and exits 1 instead of a stack trace (#29).
- Extraction few-shot examples carry `confidence` so small local models emit it instead of defaulting to 0.5 (#23).
